## 1. What is Vite? (+ Pros of Vite)

**Simple words:** Vite (French for "fast") is a dev tool that starts your project instantly and hot-reloads the browser the millisecond you save a file.

**Official definition:** Vite is a **frontend build tool** that provides a fast **development server** (native ES modules) and an optimized production **bundler**.

**Evolution (2026 current):** Vite ≤7 = esbuild (dev) + Rollup (prod). **Vite 8+ = Rolldown** — a single **Rust** bundler (Rollup-compatible API) that is **10–30× faster than Rollup**, on par with esbuild. Exam answer: say the classic pair first, then "now unified as Rolldown in Vite 8."

**Why it exists:** CRA/Webpack bundle your *entire* app before the server starts. Vite only transforms the file you're using → near-instant startup.

**Pros of Vite (exam list):**
- ⚡ **Instant dev server start** (no full bundle upfront)
- 🔥 **HMR** — updates only the changed module
- 📦 **Optimized production build** (bundler + code splitting — Rolldown in Vite 8+)
- 🧩 Simple, readable `vite.config.js` (no eject)
- 🌲 **Tree shaking** out of the box (ESM enables it)
- CRA is deprecated → Vite is the React-recommended default

**Vite vs CRA:**

| | CRA (Webpack) | Vite |
|---|---|---|
| Dev server start | Slow — bundles everything first | **Instant** |
| Rebuild on save | Full rebundle | **HMR** — changed module only |
| Config | Hidden / eject needed | Plain `vite.config.js` |
| Status | Deprecated | **Officially recommended** |

**Terms to mention in exam:** Vite, build tool, development server, HMR, CRA, optimized build, tree shaking.

Docs: https://vite.dev/guide/why-vite

## 2. Project setup + NPM

```bash
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
```

**NPM (Node Package Manager):**
- **Simple words:** the folder-of-tools installer for JS. `package.json` = the shopping list; `node_modules/` = the actual tools.
- `npm install` reads `package.json` and downloads everything (and locks exact versions via the lockfile).
- `npm run dev` runs the `"dev"` script from `package.json` (`"dev": "vite"`).

**Terms to mention in exam:** NPM, package.json, scripts, `npm install`, `npm create vite`.

Docs: https://vite.dev/guide/

## 3. package.json vs package-lock.json

| | `package.json` | `package-lock.json` |
|---|---|---|
| Purpose | **Declares** dependencies + scripts + metadata | **Freezes** the exact full tree installed |
| Versions | `"react": "^19.0.0"` (range, allows updates) | Exact versions + integrity hashes for every package |
| Commit to git? | ✅ yes | ✅ yes (critical for same install everywhere) |
| Hand-edited? | yes (add scripts/deps) | **never** — auto-generated by npm |

**Why the lockfile exists:** `^19.0.0` could resolve to 19.1 next month → "works on my machine" bugs. Lockfile guarantees teammate/CI installs the **identical** tree.

**Terms to mention in exam:** semver range, exact versions, reproducible installs, integrity hash.

Docs: https://docs.npmjs.com/cli/v10/configuring-npm/package-json

## 4. Project structure

```
my-app/
├── index.html          ← entry HTML at ROOT (Vite — unlike CRA)
├── vite.config.js
├── package.json
├── package-lock.json
└── src/
    ├── main.jsx        ← JS entry: mounts React onto #root
    ├── App.jsx
    └── index.css
```

`index.html` contains:

```html
<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>
```

`type="module"` → native **ES Modules** → Vite serves files without bundling in dev.

**Terms to mention in exam:** `index.html` at root, `type="module"`, `src/main.jsx`.

## 5. vite.config.js — line by line

```js
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react()],
  server: { port: 6161, open: true },
});
```

| Word | Meaning |
|---|---|
| `defineConfig(...)` | Helper for autocomplete; plain `export default {}` also works |
| `plugins: [react()]` | Adds **JSX transform + Fast Refresh** (HMR that keeps component state) |
| `server.port` | Custom port (default 5173) |
| `server.open: true` | Auto-open browser on start |

**Why a plugin?** Vite is framework-agnostic; without the plugin, JSX wouldn't transform correctly with React Fast Refresh.

Docs: https://vite.dev/config/

## 6. main.jsx — the pre-built syntax (memorize)

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

| Piece | Meaning |
|---|---|
| `createRoot(el)` | React 18+ API creating a **root** React manages (replaces `ReactDOM.render`) |
| `getElementById("root")` | The mount point — empty `<div id="root">` (EJS analogy: the `<%- body %>` slot) |
| `.render(...)` | Put this JSX tree inside that div |
| `<StrictMode>` | Dev-only wrapper: **double-invokes** effects/renders to surface bugs |
| `<App />` | Root component — all UI descends from here |

**Why console.log in App.jsx appears twice:** StrictMode intentionally **mounts → unmounts → remounts** components in dev to expose effects without cleanup. Production logs once. Fix noise: remove StrictMode or ignore — it's a feature, not a bug.

**Enabling/disabling StrictMode:** it's on by default in `main.jsx`. Disable = delete the `<StrictMode>` wrapper. No production impact either way (stripped from prod builds' behavior... actually StrictMode renders children the same but double-invocation is dev-only).

**Terms to mention in exam:** `createRoot`, mount point, `.render()`, StrictMode, double-invocation.

Docs: https://react.dev/reference/react/StrictMode

## 7. Babel, transpilers, Webpack

**Compiler vs Transpiler:**

| | Transpiler | Compiler |
|---|---|---|
| Job | Source → source, **same level** (JSX → JS, TS → JS) | Source → **lower level** (JS → machine code) |
| Example | Babel, SWC, esbuild (transform mode) | GCC, V8 (JS engine), tsc (to bytecode-ish) |
| Analogy | Translator FR→EN | Builder: blueprint → building |

**Babel:** the classic **JS/transpiler** that turns JSX → `React.createElement(...)` and modern JS → older JS for browsers. With Vite, **esbuild/SWC** do this natively (10–100× faster) — Babel still powers many plugins.

```jsx
// JSX in
const el = <h1>Hi</h1>;
// Babel out (classic runtime)
const el = React.createElement("h1", null, "Hi");
```

**Webpack:** the older **bundler** (CRA's engine). Takes all modules → builds a dependency graph → emits bundles. Slow cold starts = why Vite won. Vite used esbuild (dev) + Rollup (prod); **Vite 8+ unifies both into Rolldown (Rust)**.

**Terms to mention in exam:** Babel, transpiler, JSX transform, Webpack = bundler, esbuild, dependency graph, Rolldown (Vite 8 Rust bundler, 10–30× faster than Rollup).

Docs: https://babeljs.io/docs/latest/ · https://webpack.js.org/concepts/

## 8. ES Modules, imports, exports

**ESM (ECMAScript Modules):** the JS standard for splitting code across files (`import` / `export`). Browser-native (that `type="module"` script tag).

```jsx
import { defineConfig } from "vite";   // named import — curly braces REQUIRED
import App from "./App.jsx";           // default import — NO curly braces
```

**Curly braces rule:** braces = **named** import/export. Default import/export = no braces. You **cannot** use a named export without braces (common exam trap: "Using named exports without curly braces" → ❌ won't work).

**Named vs default export:**

```jsx
// named — import with { }
export function helper() {}
import { helper } from "./utils";

// default — exactly ONE per file, import without braces, any local name
export default function App() {}
import Whatever from "./App";   // local name can differ!
```

| | Named | Default |
|---|---|---|
| Per file | Unlimited | **Exactly one** |
| Import syntax | `import { x } from` | `import x from` |
| Renaming on import | `import { x as y }` | free (name is local) |
| Tree-shaking | ✅ better | OK |

**Destructuring** (pulling fields out of objects/arrays — why props work):

```jsx
function Greeting({ name, age }) {   // = props.name, props.age
  return <h1>{name}, {age}</h1>;
}
const [count, setCount] = useState(0);  // array destructuring
```

**Terms to mention in exam:** ES modules, named vs default export, curly braces, destructuring, one default per file.

Docs: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import

## 9. HMR, tree shaking

**Hot Module Replacement (HMR):**
- **Simple words:** swapping a changed file into the running app **without a full page reload** — your counter stays at 5 after you fix a CSS bug.
- **Official:** Vite/Webpack feature where the dev server pushes updated modules over a socket; React Fast Refresh re-runs the component while **preserving component state** where safe.
- Full reload = lose all state + slower; HMR = ms-level, state kept.

**Tree shaking:**
- **Simple words:** the bundler **deletes unused exports** from your production bundle (like shaking dead leaves off a tree).
- **Official:** dead-code elimination based on **static ES module analysis** — if you never `import { helper }`, it never ships.
- Requires ESM (why `import/export` > CommonJS `require` for bundles). Vite/Rollup do it in prod builds.

**Terms to mention in exam:** HMR, Fast Refresh, no full reload, tree shaking, dead code elimination, ESM static analysis.

Docs: https://vite.dev/guide/features.html#hmr · https://developer.mozilla.org/en-US/docs/Glossary/Tree_shaking
