Lesson 3: Schema Design & Indexes

Mission tie-in: "When would you embed vs reference?" and "How do indexes work?" are classic oral exam questions.

1. Schema Design

Dynamic Schema

Each document can have different fields. No migration needed:

db.users.insertOne({ name: "Alice", role: "admin", permissions: ["read", "write"] })
db.users.insertOne({ name: "Bob", role: "viewer" })  // no permissions field—OK!

Embedding

Nest related data inside the parent document:

{
  _id: 1,
  name: "Alice",
  address: { street: "123 Main", city: "NYC", zip: "10001" },
  orders: [
    { product: "Laptop", amount: 1200 },
    { product: "Mouse", amount: 25 }
  ]
}

Use when: data is always accessed together, 1-to-few relationships.

Referencing

Store an ID that points to another document:

// Order document
{ _id: 101, customerId: 1, product: "Laptop", amount: 1200 }

// Customer document
{ _id: 1, name: "Alice", email: "alice@example.com" }

Use when: 1-to-many, many-to-many, or data grows independently.

EmbeddingReferencing
Query count1 queryMultiple queries or $lookup
AtomicitySingle doc (atomic)Multi-doc (needs transactions)
Doc sizeGrows with embedded data (max 16 MB)Stays small
DuplicationPossible (if referenced elsewhere)Single source of truth

Real-world Rule of Thumb

  • 1-to-few (e.g., addresses per user) → Embed
  • 1-to-many (e.g., orders per customer) → Reference
  • Many-to-many (e.g., students ↔ courses) → Reference

2. Indexes

Why Indexes Matter

Without an index: MongoDB does a COLLSCAN — reads every document. With an index: IXSCAN — jumps directly to matching docs. Like looking up a word in a book via the index vs reading every page.

Creating Indexes

db.products.createIndex({ name: 1 })               // single-field ascending
db.products.createIndex({ category: 1, price: -1 }) // compound
db.products.createIndex({ description: "text" })    // full-text search
db.products.createIndex({ createdAt: 1 }, { expireAfterSeconds: 86400 }) // TTL

Compound index order matters: put equality filters first, then sort, then range.

Check if Index is Used

db.products.find({ name: "Laptop" }).explain("executionStats")

Look for "stage": "IXSCAN" (good) vs "COLLSCAN" (bad).

Covered Query

A query answered entirely from the index — no documents read. Check totalDocsExamined = 0 in explain().

Quick Quiz

1. Would you embed or reference: storing a user's shipping addresses?

Answer

Embed — 1-to-few (typically 1-3 addresses). Accessed together with user data.

2. What about storing all orders for a customer over their lifetime?

Answer

Reference — 1-to-many (hundreds of orders). Orders grow independently.

3. What does createIndex({ age: 1, name: -1 }) create?

Answer

A compound index: ascending on age, descending on name. Supports queries filtering by age alone, or age + name.

4. How do you check if a query uses an index?

Answer

Use .explain("executionStats"). Look for "stage": "IXSCAN" (index scan) or "COLLSCAN" (collection scan).

5. What is a covered query?

Answer

All fields needed by the query exist in the index. No documents need to be read — fastest possible query.
